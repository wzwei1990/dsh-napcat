## 1. 会话排队 + 看门狗误判（P0）

### 现象
- GUI 里出现「3 条排队消息」，都是同一个群的不同群友消息（截图已确认）
- 长任务（如 5 分钟的深度研究）期间，后续消息排队；过一会日志出现：
  `会话没有开始执行（可能已归档或失效），换新会话重投: group:660610917`
- 结果：**新建一个 `[dsh-napcat]` 会话**，原来的上下文/记忆断掉，且可能重复回复

### 根因（代码位置）

| 位置 | 现状 |
|---|---|
| `bridge.ts:2240 dispatch()` | 直接 `chat.agent.followup(...)`，**没有 busy 判断**；并发消息全部进 DSH 的 followup 队列（GUI 显示"排队消息"） |
| `bridge.ts:2299 armWatchdog()` | 只在 `chat.fresh !== true`（复用会话）时武装；**但排队中的消息也要等前一轮结束才 turn/start** |
| `bridge.ts:2310` | 判定条件用 `chat.lastEventAt > chat.dispatchedAt`，排队期间没有事件 → 两次超时（默认 10s×2 轮）就判死 |
| `bridge.ts:2317` | 判死 → `recoverAndRetry` |
| `bridge.ts:2342 recoverChat()` | 直接 `sessionSuffixes.set(key, Date.now())` 换会话 id → **新会话 = 上下文丢失** |

一句话：**"排队等得久"被误判成"会话死了"**，然后为了"救活"反而杀掉上下文。

### 方案（四层，建议全做）

**A. busy 状态机**
```
ChatState.busy: boolean
  turn/start → busy = true
  turn/end   → busy = false
```
- busy 时 `dispatch()` 不进 followup，而是进 `chat.pendingBuffer`
- busy 时不武装看门狗（排队等待不算异常）

**B. 合并窗口（替代 N 条排队）**
busy 期间收到的消息进缓冲（记录发送人/时间/是否 @我）：
- turn/end 后，若缓冲里有 **@我 / 指令 / 提问** → 合并成一条投递：
  `【多人同时说话】A：… ／ B：… ／（@我）C：…`
- 纯闲聊 → 只作为上下文，不投递（避免"排队 3 条"）
- 一个 turn 结束后**最多再投递 1 条**

**C. 去重与优先级**
- 同一人连续多条 → 合并
- 优先级：@我 > 提问 > 链接 > 闲聊
- 每会话 pending 上限 1 条 dispatch；超出只更新"最新话题摘要"

**D. 看门狗改造**
```
if (chat.busy) 不判死
else 超时 → 先「重投同一会话」（不换 session）
     连续 2 次失败 → 才换新会话，并在首条消息里带「上一会话摘要」
```

**E. 可选：打断**
只对显式指令（"停"、"别说了"、"打断"）调 `agent.abort()`，其余一律合并。

### 预期
- GUI 不再出现「N 条排队消息」
- 长任务期间新消息最多等一轮，之后合并回复
- 不再无故新建 `[dsh-napcat]` 会话

## 2. 表情包 vs 普通图片（P1）

### 现状
`media.ts` 把图片存到收件箱，注入 `[图片: path]`；模型看到图就会"描述内容"——表情包也被当内容描述。

### 判据（按可靠性排序，越靠前越便宜）

| 级别 | 判据 | 成本 |
|---|---|---|
| 1 | **OneBot 元数据**：`image.sub_type`、`summary`（NapCat 常见 `[动画表情]`）、扩展名 `.gif/.webp`、小尺寸方图、透明通道 | 0 |
| 2 | **本地表情库匹配**：`dsh-meme` 已有 146 张带 tag（happy/angry/sad…）→ 感知哈希/颜色直方图匹配，命中直接得到情绪 | 0（纯本地） |
| 3 | **视觉分类兜底**：一次廉价多模态调用 → `{类型: 表情包/截图/照片/其他, 情绪: 开心/生气/无语/...}` | ≈1 次小图请求 |
| 4 | **上下文信号**：连续短句 + 图片、图片无配文（典型斗图） | 0 |

### 注入形态

| 判定 | 注入 |
|---|---|
| 表情包 | `[表情包: 得意（群友情绪参考，不用描述）]` —— **不给路径**，不要求描述 |
| 普通图片/截图 | 保持 `[图片: path]` |
| 不确定 | 现状（模型自己判断） |

### 关键点
- 模型提示里加一句硬规则：「`[表情包:…]` 只作为情绪/语气参考，不要描述画面内容」
- 库匹配优先：群友常用的图基本都是收藏的表情包，命中率高
- 视觉分类只在 1/2 都没命中时调用，控制成本

## 3. 人格系统（P2）

### 现状
`config.ts:67 personaOverrides`：一行文本 `group:<群号>=<人设>`，静态、无成长、无关系。

### 参考项目（GitHub star 实测）

| 项目 | ★ | 授权 | 可借鉴 |
|---|---|---|---|
| **SillyTavern** | 35431 | AGPL-3.0 | **Character Card V2/V3** 字段规范（description / personality / scenario / example dialogues）+ 世界书（lorebook） |
| **flizzywine/dsh-tavern** | 1524 | AGPL-3.0 | DSH 里的实现：人物卡直接导入、**Agent 自行检索记忆**（不是提前压缩注入）、Skill 化写作 |
| **st-memory-enhancement** | 1537 | 无 | 长期记忆分层（摘要 / 细节 / 关系） |
| **AstrBot** | 46450 | AGPL-3.0 | 人格配置 + 多平台会话隔离 |
| **whyever77/dafeiyu-astrbot** | 779 | MIT | 大肥鱼鲸鱼娘 bot：记忆 + 主动找人（和我们的桌宠同一 IP 形象） |
| ARCHEON999/Companion-AI-Memory | 58 | 无 | 冷热记忆 + 性格状态方案 |

### 设计：四层人格

**L1 核心人设卡（长期不变）**
```jsonc
{
  "name": "大肥鱼",
  "style": "毒舌但心软，短句，爱用鱼梗",
  "catchphrases": ["……啊这", "鱼生艰难"],
  "values": ["护短", "反内卷"],
  "boundaries": ["不聊政治", "不评价群友长相"],
  "examples": [{ "user": "在吗", "reply": "在，鱼还没睡" }]
}
```
→ 兼容 SillyTavern 卡格式，可直接导入别人的卡。

**L2 关系印象（每个群友一条）**
```jsonc
{ "qq": "123", "称呼": "老王", "亲密度": 0.7, "标签": ["技术宅", "爱发车"], "雷点": ["别提他掉头发"] }
```
→ 由记忆自动沉淀，不需要手写。

**L3 成长事件（append-only）**
```jsonc
{ "at": "2026-11-09", "who": "群友A", "event": "被夸会写诗", "effect": "+0.1 自信" }
```
→ 每周一次「反思 turn」把它汇总成「本周性格小结」，写回人设卡的可变区。

**L4 场景适配**
| 场景 | 语气 |
|---|---|
| 群聊 | 短句、玩梗、少解释、可发表情包 |
| 私聊 | 耐心、给步骤、少用梗 |
| @我 提问 | 直接回答，不寒暄 |
| 被打断 | 一句话收尾 |

### 落地形态
- 人设卡：`~/.dsh/dsh-napcat/persona/*.json`（热加载）
- 关系卡：走已有 `mnemon` 长期记忆（每群一个 Memory Space），新节点类型 `关系`/`事件`
- 工具：`napcat_persona_get / set / import`（设置页可视化编辑 + 导入 ST 卡）
- 注入策略：系统提示只放 **L1 + 当前会话 L2 摘要**；L3 细节靠检索（`mnemon_recall`），避免上下文膨胀
- 兼容：现有 `personaOverrides` 保留为「快速覆盖」，优先级高于 L1

## 4. 小红书 / 网易云链接（P3）

### 现状
只有 `BiliLink`（B 站），其他域名当纯文本。

### 方案：链接解析注册表
```
detectLink(text) → 按域名分发
  ├─ bilibili      （已有）
  ├─ xiaohongshu   （新增）
  ├─ netease-music （新增）
  └─ generic       （og:meta 兜底）
```

| 域 | 取数方式 | 说明 |
|---|---|---|
| **小红书** | 短链 `xhslink.com` → 302 到 `xiaohongshu.com/explore/<id>` → 抓 `og:title/og:description/og:image` | 免登录只能拿标题/摘要/首图；更深内容需要 cookie |
| 小红书（进阶） | **XHS-Downloader**（★13241，GPL-3.0） | 支持作品/评论采集，需要用户自备 cookie；按「本地工具」方式集成，不 vendor |
| **网易云** | `163cn.tv` / `music.163.com` 分享链接 → 歌曲 id → 官方 `api/song/detail` + `api/song/lyric`（免登录） | 拿到歌名/歌手/歌词片段；热评可选 |
| 通用 | `<meta property="og:*">` | 20s 超时，失败静默 |

### 注入形态（与 BiliLink 一致）
```
【群友刚发的链接，已看过】标题：…
内容概要：…
→ 像看过一样随口接一句，不要播报、不要贴链接、不要列点。
```

### 超时与降级
- 每个域 20s 超时（沿用 `bililink.ts` 的 `withTimeout`）
- 失败：静默（不打断对话），只记 debug 日志
- 小红书短链解析失败时，退化为「只识别平台名 + 原链接」，让模型自己说一句

## 5. 优先级与工作量

| 项 | 优先级 | 改动面 | 预估 |
|---|---|---|---|
| 1 会话排队 / 看门狗 | **P0** | `bridge.ts`（状态机 + 合并缓冲 + watchdog） | 半天 |
| 2 表情包识别 | P1 | `media.ts` + 注入 + 分类器 + 提示词 | 半天 |
| 3 人格系统 | P2 | 新 `persona.ts` + 关系卡（mnemon）+ 设置页 | 2–3 天 |
| 4 链接解析 | P3 | 新 `linkresolver.ts` + 2 个域实现 | 1 天 |

**建议顺序**：1 → 2 → 4 → 3（前三件能立刻改善群聊体验，人格系统是长期工程）。
